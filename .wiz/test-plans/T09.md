# T09 — Endpoints + Playground

## Acceptance criteria
- Endpoints page table: ChainBadge, name, monospaced id, copyable `/api/v1/rpc/<id>` URL, created date.
- CreateEndpointForm rendered only when `canCreateEndpoint`.
- Delete button per row only when `canDeleteEndpoint`.
- Playground: endpoint dropdown, method input, params textarea (JSON array, safe parse), Send → POST /api/v1/rpc/:id.
- Response panel: pretty-printed JSON + observed latency.
- Sample chips: EVM list for {eth,avax} (5 methods), BTC list for btc (4 methods).
- ToastHost surfaces copy / create / delete events.

## Test scenarios
1. Endpoints table renders one row per endpoint with name + id.
2. Admin role sees Create form + Delete buttons.
3. Viewer role sees neither Create form nor Delete buttons.
4. Developer role sees Create but no Delete.
5. CopyButton click triggers a toast + writes to clipboard.
6. Playground: viewer cannot click Send (button hidden/disabled).
7. Playground: clicking an EVM sample chip fills method + params.
8. Playground: chip list switches to BTC when btc endpoint is selected.
9. Playground: invalid JSON params shows an error message.
10. Playground: Send posts to the right URL and renders the response.
