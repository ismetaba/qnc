# T06 — API proxy + metrics + logs + usage + nodes

## Acceptance criteria
- `proxy.ts`: forwards body via `fetch` to mock node URL; measures duration via `performance.now()`; records `RpcLogEntry`.
- `POST /v1/rpc/:endpointId` proxies and surfaces RPC errors as ok=true responses (the wrapper itself is ok).
- `metrics.ts`: percentile helper; `computeMetrics(endpointId, windowMs)`; route `GET /v1/metrics?endpointId&windowMs`.
- `GET /v1/logs?endpointId&limit` returns reverse-chronological log slice.
- `GET /v1/usage` returns totals + monthToDate using Discovery plan ($49 + $25/M overage above 80M).
- `GET /v1/nodes` pings each mock node and returns `NodeHealth[]`.

## Test scenarios
1. `percentile(arr, p)` works for canonical fixed input (e.g., 1..100, p50, p95, p99).
2. `computeMetrics` filters by endpointId + window; correct counts/errors/percentiles/byMethod.
3. `POST /v1/rpc/:endpointId` mocked fetch — pushes entry to rpcLog with chain matching endpoint.
4. POST with unknown endpoint id returns 404.
5. `GET /v1/logs?endpointId=X&limit=N` returns at most N entries in reverse chronological order.
6. `GET /v1/usage` echoes totals; monthToDate.estimatedCostUsd = 49 + (overage/1e6) * 25.
7. `GET /v1/nodes` with mocked fetch returns 3 NodeHealth objects keyed by chain.
